# 探索的テスト計画の資料に共通する条件

この条件は、実行の担当が plan-exploratory-testing で作った探索的テスト計画の資料（以下、資料）と grill の記録（以下、記録）を判定するためのもので、どの範囲の探索計画にも当てる。ケースに固有の条件は、この後ろに続く。条件は判断の型だけを書き、正しい資料の中身は書かない。どの条件も、ほかの条件の出来、文体、見出しの形では判定しない。各条件の「重み」は点数にまとめるときの値で、判定の厳しさは変えない。重み3は利用者の原則の芯（推測で埋めない、一つの判断は一か所が持つ、同じ欠陥を最小の境界へ移す）、重み2は資料の骨組み、重み1は細部である。資料や記録が存在しない、または空のときは、それを読む条件はすべて FAIL とする。

実行の担当は、対象リポジトリ（要件と設計資料だけの手元の git repository）、確定済みのテスト戦略（`materials/test-strategy/`）、依頼と scope を渡された。grill の問いには、資料と戦略から決まることで答え、決まらなければ推奨を仮置きして資料の未決に書くよう指示されていた。

## 何を探索するか

### explore-unknowns

重み: 3

PASS：探索の対象は、自動テストが確かめていない未知（別の状態の系列、複数の境界の組み合わせ、利用者の判断や回復のしやすさ、診断のしやすさ、シナリオ資料が意図して省いた残余リスク）で、既知の期待を同じ手順で確かめ直す回帰を探索に置いていない。自動テストが足りないことは、探索で代わりにせず、別に記録している。

FAIL：既知の期待の確認や回帰を探索の中心にしている、または自動テストの不足を探索で埋めるとしている。

### evidence-not-assumed

重み: 3

PASS：対象リポジトリにコードもテストも無いことを踏まえ、自動テストの証拠を「存在しない」か「未実行」として扱い、実行済みの証拠として数えていない。残余リスクは、戦略とシナリオ資料（あれば）と要件から導かれ、根拠の箇所が書かれている。

FAIL：存在しないテストや実行結果を、証拠として数えている。

## charter と記録

### charter-direction

重み: 2

PASS：charter は、対象、試す方向、観察する品質を一文で表し、操作を逐次に固定していない。時間枠は対象と使える時間から決め、根拠の無い固定の値にしていない。重要な枝が出たときの扱い（thread か後続の charter）を書いている。

FAIL：charter が手順の列になっている、または charter に対象、方向、観察する品質のどれかが無い。

### oracle-grounded

重み: 2

PASS：異常を疑う根拠（要件や業務知識との不一致、別の経路や順序で保たれるべき関係、回復できない、状態を理解できない、診断できない）を書き、期待の根拠が無いときは欠陥と決めつけず要件の持ち主へ判断を戻すとしている。

FAIL：期待の根拠を示さずに異常を判定する、または根拠の無い期待を欠陥として扱う。

### record-evidence

重み: 2

PASS：発見の記録に、元の charter、環境と初期状態、具体的な入力と操作の列、実際の結果、期待と根拠、再現した回数と条件、再現しなかった条件、関連するログや時刻を残すよう求め、発見を仕様どおり、期待の根拠が不明、追加の探索が要る、再現できる欠陥に分けている。

FAIL：記録に残すもののうち、再現の条件か期待の根拠が無い。または、発見の分け方が無い。

## 自動チェックへの引き継ぎ

### handoff-smallest-level

重み: 3

PASS：再現できる欠陥は、発見したときの操作のレベルではなく、戦略の規則に従って同じ失敗を再現できる最小の担当レベルとサイズへ下げ、依存を一つずつ外して最小の境界を見つける手順を書いている。修正を始める条件を、そのチェックが未修正のコードで意図した理由により失敗することとし、環境や fixture の不良による失敗を数えない。自動化しない場合の条件と、状態、次の持ち主、再開の条件を残している。

FAIL：発見した操作をそのまま E2E や高水準の回帰テストにする、赤の条件が無い、または自動化しないときの扱いが無い。

## 推測で埋めない

### hypothesis-marked

重み: 3

PASS：要件、設計資料、戦略から決まらない方針（環境、時間枠、実施者、使う道具）と、記録で推奨を仮置きした答えは、仮説と分かる語で書かれ、根拠と見直す条件が添えられている。存在しない環境やツールを事実として書いていない。

FAIL：資料から決まらない方針や存在しない環境が、断りなく事実として書かれている。

### owner-not-rewritten

重み: 2

PASS：設計資料とテスト戦略を書き換えていない。性能、負荷、セキュリティ、アクセシビリティの専門試験は、scope で指定されていない限り扱っていない。

FAIL：設計資料か戦略を書き換えた形跡がある、または指定の無い専門試験を計画している。

## grill

### grill-only-outcome-changing

重み: 1

PASS：記録にある問いは、答えで探索の目的、残余リスク、環境、期待の根拠、引き継ぎ先が変わるものだけである。問いが無いときは、問わなかった理由が記録か報告にある。

FAIL：資料から一つに決まることを問うている問いがある。または、問いが無く、その理由も無い。
