# X のクローンのホームタイムラインへの反映に固有の条件

ホームタイムラインへの反映は、フォローの変化とポストの配信が別々に、非同期に、止まっても後から再開される形で進む。高ファンアウトの投稿者の扱いや、フォローを外した後の件数の不足のように、要件が意図して決めた振る舞いも多い。この条件は、その題材で探索計画が外しやすい判断を型にしたものである。

### xx-order-and-interleave

重み: 3

PASS：フォローとフォロー解除とポストが短い間に入れ替わって起きる系列（フォローした直後に外す、外した直後に相手がポストする、反映の途中で次の変化が来るなど）を、単一の操作では分からない未知として探索の対象にし、保たれるべき関係（外した相手のポストが残らない、同じポストを二度見せない、など要件や業務知識にあるもの）を異常を疑う根拠にしている。

FAIL：単一の操作の確認だけを探索にしている、または系列の探索に期待の根拠が無い。

### xx-intended-behavior-not-defect

重み: 2

PASS：要件が意図して決めた振る舞い（反映が遅れて見えること、件数の不足を補わないことなど、要件に書かれたもの）を、欠陥と決めつけず、仕様どおりか期待の根拠が不明かとして扱う方針がある。

FAIL：要件が決めた振る舞いを欠陥の候補として扱い、根拠の確かめ方が無い。

### xx-diagnosability

重み: 2

PASS：反映が止まったり遅れたりしたときに、利用者と運用者が状態を理解でき、原因を診断できるかを観察する品質に含め、診断できないことも発見として記録するとしている。

FAIL：診断のしやすさを観察の対象にしていない。
