# X のクローンのフォローの境界に固有の条件

フォローする、フォローを外すの境界は、本人だけが行えること、上限と重複の禁止、同じ要求の再送、成功の後に反映の要求が積まれることを持つ。この条件は、その題材で境界シナリオが外しやすい判断を型にしたものである。

### xa-principal-from-auth

重み: 3

PASS：フォローとフォロー解除の主体（誰がフォロワーか）は、認証された呼び手から決まり、要求の中で申告された利用者を信じないことを、境界で確かめるシナリオがある。未登録の呼び手と、ほかの利用者として行う要求の外部表現と、状態が変わらないことを観測している。

FAIL：主体を要求の中の値で決める前提でシナリオを書いている、または認証・認可の結果を確かめるシナリオが無い。

### xa-limit-and-duplicate-placed-below

重み: 2

PASS：フォロー上限（5,000人の前後）と同じ相手の重複、自分自身のフォローの判断は、業務判断か永続化のレベルを主担当にし、境界には外部表現を確かめる代表例だけを残している。同時に二つのフォローが進む場面は、実行順に依らない形で永続化のレベルに送っている。

FAIL：上限の境界値や重複の組み合わせを境界のシナリオで網羅している、または同時の場面を境界で実行順任せに確かめている。

### xa-reflection-request-observed

重み: 2

PASS：成功したフォローとフォロー解除について、応答だけでなく、操作後に外から観測できる副作用（反映の要求が一つ積まれること、拒否では積まれないこと）を観測結果に含めている。反映が終わるまでを境界のシナリオで待っていない。

FAIL：成功と拒否の副作用（反映の要求）を観測していない、または反映の完了まで境界のシナリオで待っている。
