# testing-strategy の意味評価

`scenarios.json`は、テスト戦略、プログラム境界シナリオ、E2Eシナリオ、探索的テスト計画の主要な利用場面、責務外、判断が切り替わる境界を人が評価するためのfixtureである。構造検査の合格を、成果内容の妥当性の証拠にしない。

## 評価方法

1. 対象ケースの`messages`を公開skillへ渡す。
2. `criteria`ごとに、回答または保存された戦略の根拠箇所を記録する。
3. 対話や保存が必要なケースは実セッションで行う。
4. 観測できなかった項目を成功扱いにせず「未観測」とする。

典型例は資料だけの戦略設計、具体的な境界シナリオ、重要価値経路、既存自動テスト後の探索計画である。負例はテストコード実装だけの依頼、抽象的な不正入力、境界値を網羅するE2E、発見時の高水準操作をそのまま回帰テストへ固定する依頼である。境界例は、テスト名と依存範囲が食い違うサイズ分類、機械可読な定義を持たない境界、一度だけの観察、oracle不明の発見で確かめる。
