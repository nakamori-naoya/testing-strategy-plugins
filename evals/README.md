# testing-strategy の意味評価

`scenarios.json`は、`design-test-strategy`の主要な利用場面、責務外、判断が切り替わる境界を人が評価するためのfixtureである。構造検査の合格を、戦略内容の妥当性の証拠にしない。

## 評価方法

1. 対象ケースの`messages`を公開skillへ渡す。
2. `criteria`ごとに、回答または保存された戦略の根拠箇所を記録する。
3. 対話や保存が必要なケースは実セッションで行う。
4. 観測できなかった項目を成功扱いにせず「未観測」とする。

典型例は資料だけのリポジトリ、負例はテストコード実装だけの依頼、境界例はテスト名と依存範囲が食い違うサイズ分類である。技術中立性は、RDBもHTTP APIも無い題材で確かめる。
