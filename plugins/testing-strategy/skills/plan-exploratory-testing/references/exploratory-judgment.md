# 探索から再現・自動チェック・修正へつなぐ判断基準

このreferenceは、自動テスト後に残る未知を探索し、その発見を再現可能な証拠へ固め、欠陥を再現できる最小レベルの自動チェックとTDDによる修正へ渡す判断を所有する。探索の実行、テストコード実装、バグ修正そのものは所有しない。

## 探索対象

探索は既知の期待を同じ手順で再確認する回帰テストではない。次を優先する。

- 自動テストが単一操作だけを確認し、別の状態系列が未知な箇所
- 複数境界の組み合わせで現れる創発的な振る舞い
- 利用者の判断、分かりやすさ、回復可能性など、固定oracleだけでは評価しにくい品質
- 変更差分と過去障害が交差する箇所
- ログ、エラー、状態表示など、失敗時の診断可能性
- 境界・E2Eシナリオで意図的に省略した残余リスク

既存自動テストが不足する場合、探索で回帰保証を代替しない。不足を独立して記録し、それでも探索する理由を品質リスクから説明する。

## charterとthread

charterは、対象、試す方向、観察する品質を一文で表す。逐次操作を固定せず、実施者が観察から次の行動を選べる余地を持たせる。

探索中に重要な枝が生じたら、元のmissionを失わないようthreadとして追跡する。現在のcharterで扱い切れない枝は、後続charterへ分ける。

## oracle

異常を疑う根拠を一つに限定しない。

- 要件、業務知識、データモデル、境界契約との不一致
- 同じ目的を持つ別経路または以前の版との不一致
- 操作の順序を変えても保たれるべき関係
- 入力を変えたときに予測できる結果関係
- 利用者が回復できない、状態を理解できない、原因を診断できないこと

期待結果の根拠が無ければ欠陥と断定せず、要件またはoracleの未決へ分類する。

## 発見の証拠

発見は次を持つ。

| 要素 | 内容 |
|---|---|
| 出所 | mission、charter、thread |
| 環境 | 版、構成、主体、関連する外部条件 |
| 初期状態 | 外部から観測できる状態と必要データ |
| 刺激 | 具体入力と操作列 |
| 実際 | 観測した結果、時刻、ログ、状態、副作用 |
| 期待 | 期待結果と根拠となる正式な定義またはoracle |
| 再現 | 回数、再現した条件、再現しなかった条件、環境差 |
| 未決 | まだ区別できない原因仮説と次の観察 |

一度だけ起きた観察を、再現可能な手順として清書しない。再現しなかった条件も証拠に含める。

## 発見の分類

| 状態 | 判定 | 次の行動 |
|---|---|---|
| 仕様どおり | 期待との差がなく、新しい欠陥を示さない | 学びをdebriefへ残し、回帰テストを増やさない |
| oracle不明 | 実際の結果は観測したが、期待結果の根拠が決まらない | 要件または正式な定義の所有者へ判断を戻す |
| 追加探索 | 期待との差はあるが、再現条件または原因を絞れない | 観察事実と仮説を分け、新しいthreadまたはcharterを作る |
| 再現可能な欠陥 | 別の実施者が同じ初期状態、入力、操作列で期待との差を観測できる | 最小レベルの失敗する自動チェックへ渡す |

これらは探索の成否ではなく、学習を次へ渡す状態である。

## 欠陥を最小レベルへ下げる

発見時の画面操作、API列、E2E経路をそのまま自動化先にしない。同じ失敗を再現するために本当に必要な依存を一つずつ外す。

1. 業務判断だけで同じ期待差が出るならSmallへ置く。
2. 実ストレージ、境界変換、単一ワーカーが必要なら該当するMediumへ置く。
3. 複数プロセス・サービスの接続または制御不能な境界が無いと期待差が消える場合だけLargeへ残す。

下げる途中で欠陥が消えた境界が、その欠陥を再現するために必要な最小依存の手掛かりになる。上位にも代表例を残す場合は、下位と異なる接続上の欠陥を検出することを説明する。

## 自動チェックとTDDへの引継ぎ

自動チェック候補には次を渡す。

- 再現可能な最小初期状態、入力、操作
- 期待結果とその根拠
- 未修正コードで観測すべき失敗
- 最小の担当レベルとSmall・Medium・Large
- 保持する実物境界と、代替する制御不能な境界
- 上位で繰り返さない範囲

修正開始の入口条件は、自動チェックが未修正コードで期待した理由により失敗することである。環境不良、fixture不備、別の既知欠陥による失敗をRedとして扱わない。

修正後は、同じチェックが通ること、既存チェックを壊さないこと、必要なら設計を整理した後も通ることを確認する。新しいチェックはcoverage mapへ回帰証拠として戻す。

## 自動化しない判断

次の場合は直ちに自動化しない。

- 期待結果の根拠が決まっていない
- 再現条件を絞れていない
- 欠陥ではなく、戦略、要件、操作性、診断可能性を見直す学びである
- 自動化の保守費用が回帰リスクを上回り、再発時の別の検出方法を持てる

自動化しない場合も、状態、根拠、次の所有者、再開条件を残す。

## 計画に残す構造

- Mission: 何について何を学ぶか
- 根拠リスク: 戦略とcoverage mapのどの残余リスクか
- Charter: 対象、試す方向、観察する品質
- Setup: 環境、データ、利用者状態、観測手段
- Heuristics: 状態、順序、割込み、回復、データ差、境界間の組み合わせ
- Oracle: 異常を疑う根拠
- Evidence: 操作メモ、時刻、入力、観測結果、ログ、再現性
- Finding disposition: 発見を次の状態へ分ける条件
- Reproduction: 再現可能な最小手順と条件差
- Automation handoff: 最小配置、サイズ、実物境界、重複排除
- Debrief: 学び、欠陥、追加探索、戦略、自動チェック、修正へ戻す事項
- Stop: missionへ十分な証拠が集まった条件、または別charterへ分ける条件
